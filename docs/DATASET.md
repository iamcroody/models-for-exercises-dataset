# Dataset description

## Source

[`jayounghoyos/exercises-dataset`](https://github.com/jayounghoyos/exercises-dataset), a public
catalog of gym and calisthenics exercises. It's a git submodule at `data/exercises-dataset`,
pinned to commit `8872272` so every run trains on the same data.

## Task

MacGyver Gym Rat: given a target muscle and a household object (like two water bottles, or a
backpack), recommend a real exercise from the catalog that trains that muscle using that
object instead of the gym equipment it normally needs. If nothing in the catalog works with
that object, say so instead of making something up.

Input:

```
I want to train my delts but I have no gym equipment. All I have is two filled water bottles.
Recommend one safe exercise and explain how to do it.

Answer in exactly this format:
Exercise: <name>
Gym equivalent: <equipment>
Adaptation: <how to use what I have>
Steps:
1. <step>
Safety: <one line>

If nothing you know of trains that muscle with that object, say so instead of inventing one.
```

Output, either a real exercise with its real steps, or a refusal pointing at an alternative.

## How the dataset was built

The catalog has no "household object" field, so the mapping is built by hand
(`scripts/01_macgyver_data.py`, `scripts/macgyver.py`):

- Only 4 equipment classes get a household stand-in: dumbbell, kettlebell, weighted, and body
  weight. Things like cables, barbells, resistance bands, and machines are left out on purpose,
  since there's no safe household equivalent for what they do.
- Exercises whose steps need equipment the object can't replace (a bench, a pull-up bar, an
  exercise ball) are dropped too, even if their main equipment tag is mapped. Found this by
  reading generated examples, not from the schema.
- Each equipment class has a handful of object phrases (like "two filled water bottles" for
  dumbbell). A few objects per class are held out of training entirely, so the val/test split
  can check whether the model actually learned the pattern (object plays the role of X) or
  just memorized specific phrases.
- Examples where no exercise exists for a (target, object) pair become refusal examples: the
  model is supposed to say so instead of inventing an exercise.

Everything that's real (exercise name, equipment, target, steps) comes straight from the
catalog. The object phrases, the adaptation sentences, and the prompt wording are written by
hand, not generated by a model.

## Size and splits

| Split | Examples | Refusals | Unseen-object |
|---|---:|---:|---:|
| train | 662 | 54 | 0 |
| val | 154 | 46 | 82 |
| test | 154 | 46 | 82 |

Split by exercise ID, stratified on target muscle, seed 42. Held-out objects only ever appear
in val/test, never train. 358 of 1324 catalog exercises are reachable this way (696 map to a
household-substitutable equipment class, 338 of those get dropped for needing extra kit the
object can't replace).

`data/processed/` is gitignored, it's derived from the pinned submodule by a seeded script.

## Language and licence

English only. Exercise metadata is MIT licensed (from the upstream dataset). Images and GIFs
are © Gym visual and aren't used here, only exercise names, targets, equipment, and text
instructions.

## Known biases and limitations

- Only 4 equipment classes are covered. Most of the catalog (cables, machines, barbells) has
  no household stand-in at all, so this only ever answers a narrow slice of "what can I train."
- The equipment-to-household mapping was picked by hand, not measured. A different set of
  authored objects could give different results.
- Refusal examples always point at the closest real alternative from train, which biases what
  "closest" means toward whatever the split happened to put there.
- The scorer checks that the named exercise is real and matches the target and equipment
  class, plus ROUGE-L on the recited steps against that exercise's real steps. It doesn't
  check that the adaptation instructions are actually safe for someone's specific body.
- 154 validation examples is small. One example moves any rate by about 0.6 points, so small
  differences between runs shouldn't be read as meaningful.
